# Implementation Plan: مدیریت درخواست تغییر

**Branch**: `001-change-request-management` | **Date**: 2026-11-16 | **Spec**: [spec.md](spec.md)

**وضعیت تصمیم‌ها**: انتخاب‌های فنی اصلی در پیام مالک محصول تأیید شده‌اند. جزئیات اجرایی این نسخه در Research تثبیت شده‌اند؛ gate سازگاری واقعی driver روی Windows/Node در T001 پیش‌نیاز Implement است.

## خلاصه

نسخهٔ اول Backend-only است و HTTP API ارائه می‌کند؛ React و Frontend در تحویل نیستند. انتخاب‌های اصلی Node.js + TypeScript + Express، SQLite محلی، ورود گذرواژه‌ای، scrypt، نشست پایدار و CLI تأمین نقش تأیید شده‌اند. منطق گردش و مجوز در Application/Domain می‌ماند و لایهٔ HTTP فقط ورودی، نتیجه و خطای قراردادی را نگاشت می‌کند. جزئیات scrypt/session/CSRF/SQLite در Research تثبیت شده‌اند؛ gate سازگاری native driver روی Windows پیش‌نیاز اجراست.

## زمینهٔ فنی

**زبان/نسخه**: Node.js 26 LTS و TypeScript تأیید شده‌اند. Node `26.13.1` baseline بررسی‌شده است؛ T001 نسخهٔ patch جاری و نسخه‌های دقیق همهٔ packageها را pin و با lockfile ثبت می‌کند.

**وابستگی‌های اصلی**: Express 5، TypeScript و SQLite driver `better-sqlite3@13.1.1` تأیید شده‌اند؛ ابزارهای آزمون و نسخه‌های دقیق در T001 pin می‌شوند. مسیر نصب محلی تکرارپذیر از Node `26.13.1` و npm `12.2.2` استفاده می‌کند. npm 12 اسکریپت‌های نصب تأییدنشده را مسدود می‌کند؛ در probe رسمی better-sqlite3، binding آمادهٔ Windows x64 از خود بسته بارگذاری شد. T001 باید این مسیر را با clean install و تمام آزمون‌های compatibility واقعاً بگذراند. این سند موفقیت نصب را ادعا نمی‌کند.

**مدیریت packageها**: یک npm project در ریشه با یک package.json و lockfile برای Backend و آزمون‌ها کافی است؛ workspace جدا لازم نیست.

**ذخیره‌سازی**: SQLite فایل محلی تأیید شده است. Account، Session، RoleGrant و ChangeRequest در همان DB قرار می‌گیرند؛ بررسی نشست/نقش/مالکیت/وضعیت/نسخه و اعمال تغییر در مرز تراکنشی مشترک انجام می‌شود. commit عملیات/لغو نقش نقطهٔ خطی‌سازی است.

**آزمون**: Node `node:test` برای منطق و HTTP/SQLite یکپارچه؛ آزمون‌های Backend و snapshot دادهٔ ذخیره‌شده الزامی‌اند.

**سکوی هدف**: اجرای محلی روی Windows با PowerShell؛ برای پایگاه داده از مسیر محلی فایل استفاده شود. جزئیات مسیر و فرمان‌ها در `quickstart.md` پیشنهاد شده‌اند.

**نوع پروژه**: یک سرویس محلی Backend با HTTP API.

**اهداف کارایی**: عدد کارایی محصولی در Spec تعیین نشده است. هیچ SLA یا نرخ درخواست جدیدی فرض نمی‌شود.

**محدودیت‌ها**: ورود با حساب فردی محلی، scrypt و Session پایدار SQLite؛ RoleGrant جاری در همان SQLite؛ CLI محدود برای provisioning؛ لغو مؤثر در commit؛ شمارش با grapheme cluster. هیچ نقش قدیمی از token مبنای مجوز نیست.

**اندازه/دامنه**: یک گردش درخواست تغییر، دو نقش، چهار وضعیت و HTTP API؛ بدون ثبت‌نام/مدیریت کاربر در محصول، حذف، تاریخچهٔ کامل توضیح‌ها یا قابلیت‌های خارج از Spec.

### پیشنهاد احراز هویت و provisioning

حساب فردی با CLI محلی ساخته می‌شود. پارامتر تثبیت‌شدهٔ hash: Node `crypto.scrypt` async با `N=2^17`, `r=8`, `p=1`, `keylen=64`, `maxmem=256 MiB`; salt تصادفیِ مولد امن رمزنگاری و یکتا، 16 بایت. پارامترها همراه رکورد ذخیره می‌شوند تا مهاجرت/rehash ممکن باشد. نشست شناسهٔ تصادفی 32 بایتی دارد؛ SQLite فقط SHA-256 شناسه را ذخیره می‌کند. نشست با idle timeout 30 دقیقه و سقف مطلق 12 ساعت منقضی می‌شود؛ زمان آخرین فعالیت در هر درخواست احرازشده به‌روزرسانی می‌شود؛ نشست منقضی هنگام ورود پاک و CLI فرمان `sessions prune` برای پاک‌سازی دستی دارد. Logout رکورد را حذف می‌کند. این چرخه روی همان DB و بدون MemoryStore اجرا می‌شود.

ورود محلی تلاش‌ها را با rolling window پانزده‌دقیقه‌ای محدود می‌کند: سقف ۶۰ تلاش برای IP و ۱۰ تلاش برای جفت login/IP؛ پاسخ عبور از سقف `429` با `Retry-After` تا خروج قدیمی‌ترین تلاش از پنجره است. تلاش ردشده پنجره را تمدید نمی‌کند؛ رکورد پس از ۲۴ ساعت پاک می‌شود؛ موفقیت bucket همان جفت را پاک می‌کند. قفل حساب سراسری/دائمی نیست، اما IP مشترک (از جمله loopback) ممکن است محدودیت موقت مشترک بسازد؛ حملهٔ توزیع‌شده با این روش به‌طور کامل مهار نمی‌شود. IP از socket مستقیم خوانده می‌شود و `X-Forwarded-For` فقط برای proxy مشخصاً مورداعتماد پذیرفته می‌شود. شناسه‌های محدودسازی HMAC شده‌اند؛ نام کاربری ناموجود و گذرواژهٔ نادرست پاسخ عمومی یکسان و مسیر scrypt مشابه دارند، بدون ادعای زمان کاملاً یکسان. گذرواژه، session ID و CSRF token نباید log شوند.

CLI افزودن/لغو RoleGrant را فقط روی همان فایل SQLite و با همان ترتیب تراکنش/قفل عملیات حساس انجام می‌دهد؛ commit تغییر RoleGrant نقطهٔ مؤثر لغو است. دسترسی به فایل DB و اجرای CLI باید به حساب OS/اپراتور مشخص با ACL ویندوز محدود شود؛ CLI در مسیر عادی HTTP/UI عرضه نمی‌شود. همین ترتیب تراکنشی commit تضمین FR-019 را برقرار می‌کند.

CSRF: توکن تصادفی 32 بایتی برای نشست، نگهداری server-side و ارسال در header `X-CSRF-Token`؛ همهٔ روش‌های تغییردهنده علاوه بر احراز نشست باید توکن و Origin دقیق را بررسی کنند. Login نیز Origin را بررسی می‌کند؛ logout توکن لازم دارد. SameSite=Lax دفاع تکمیلی است؛ CORS فقط same-origin. Cookie `HttpOnly`, `SameSite=Lax`; `Secure` فقط HTTPS. Vite مسیر `/api` را در توسعه به API proxy می‌کند. در deployment واقعی TLS اجباری و proxy مورداعتماد دقیق است. SQLite تک‌میزبان/تک‌نویسنده است؛ چند replica نیازمند بازنگری است.

`better-sqlite3` یک API هم‌زمان دارد؛ تمام Queryها و تراکنش‌ها باید کوتاه بمانند و هیچ KDF/شبکه/کار طولانی داخل تراکنش نشود. `journal_mode=WAL` حالت DB است و هنگام آماده‌سازی فایل تنظیم/تأیید می‌شود؛ `foreign_keys=ON` و `busy_timeout=5000` برای هر اتصال تازه تنظیم و تأیید می‌شوند. تراکنش حساس با `BEGIN IMMEDIATE` آغاز می‌شود. پس از SQLITE_BUSY rollback کامل و بدون retry کور پاسخ `503` با `Retry-After: 5` برمی‌گردد؛ client باید دادهٔ جاری را بخواند و فرمان را با نسخهٔ قدیمی replay نکند. T001 نصب واقعی و سازگاری driver را gate می‌کند؛ آزمون‌های T008/T040 تنظیمات هر اتصال، rollback و پاسخ HTTP را بررسی می‌کنند.

Backend همهٔ فیلدهای محدودشده را با یک helper `Intl.Segmenter('fa', {granularity:'grapheme'})` می‌شمارد؛ locale در segmentation grapheme نباید مرز متفاوت ایجاد کند. نسخهٔ Node/ICU pin و helper Backend با آزمون Unicode ثابت می‌شود. UTF-16 length و byte length معیار نیستند.

## ثبت پیچیدگی
